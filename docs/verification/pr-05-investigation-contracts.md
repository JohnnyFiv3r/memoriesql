# PR-05 investigation request identities

This internal slice validates the closed query/reuse/inspect/hydration and
checkpoint/save/resolve/release/restore/branch request envelopes from the approved
whole interface. The normative pin and matching custody are recorded in
`../approvals/pr-05-settings-reconciliation.md`; neither normative blob changes.

`parse_investigation_request` rejects duplicate JSON keys, nonfinite/native JSON
float values, invalid UTF-8, unknown fields, type coercion, unknown catalogs,
unbound contexts and invalid declared bounds. SQL syntax/composition qualification
remains the separate admitted-query kernel. An unknown catalog is unsupported,
with no downgrade. Current authorization, temporal-frame equality, delivered
evidence, compare-and-swap heads/save revisions and retained holds remain trusted
executor/persistence obligations. Syntactically valid IDs are not capabilities.

Every saved result binding carries an explicit standalone or checkpoint context.
Checkpoint contexts bind the exact selected result ID/digest and automatic or
named-save revision. No dependency-only context or inferred fallback exists.
Request fingerprints include all supplied fields, contexts and cursors; optional
field presence is preserved. Models use closed fields and immutable tuples.

`encode_result_scalar` converts native database values to the exact approved
typed wire values. `result_json_bytes` uses the existing canonical public JSON
encoder and rejects implicit native SQL values, JSON floats, invalid strings and
circular containers. It preserves Unicode bytes, signed float zero, exact
decimal values and UTC microseconds; no serializer/profile change is introduced.
SQL parameter parsing grants no anchor admission. The independently authorized
anchor set is still required by the separate kernel.
Input parameter spellings admitted by the existing kernel remain admitted,
including numeric scale/exponent forms and int8 negative zero; result-output
normalization is not an additional input restriction. Request fingerprints retain
those supplied spellings. The initial extra input normalization was removed during
qualification rather than silently reducing the approved query capability.

Checkpoint request validation rejects content whose minimum canonical manifest
already exceeds 32 KiB, including nested fact/evidence collections and JSON Unicode
escape bytes. It does not count request-only access contexts as stored manifest
content or impose a new reference-count ceiling. The closed `CheckpointManifest`
also validates the exact full allocation after trusted sequences/metadata are
assigned, with canonical timestamps, unchanged 30-day automatic lifetime and
content digest. Passing the request's lower bound is not storage admission;
the allocator must validate that final manifest before atomic publication.

Seen fictional qualification covers all action kinds, held-ancestor/context
substitution, context/cursor fingerprints, input/parent/live-frame rules, parameter
types/arrays, helper bounds, save revisions and canonical golden bytes. Installed
wheel/sdist and exact-head CI receipts belong on the PR. The first local negative
fixture accidentally shared its outer/root dictionary, so its mutation changed
both pins; the fixture was corrected to mutate only the context root. An ownership
test attempted from an uninstalled source environment correctly lacked package
metadata; that test belongs in installed qualification. Neither failure was
hidden or treated as product acceptance.

This slice adds no operation entry to the public catalog and publishes no result,
checkpoint, receipt, authorization decision or capacity claim. It executes no SQL,
database migration, model/provider call or external source access. Existing
canonical runtime/contracts/migration bytes and frozen evidence remain unchanged.
It does not satisfy atomic result/witness persistence, cross-run reauthorization,
erasure, retention holds, concurrency, cancellation/settlement, work/storage
accounting, relation-aware delivery or useful W1-W7 fit. Those remain implementation
obligations; PR-03 owns M0030 and canonical projection, PR-05 reserves M0031 onward.
The result executor must consume that qualified projection and cannot substitute
observation-only delivery. PR-06 investigation/finish/answers remain excluded.

No merge, release/version selection, publication, live evaluation, provider spend,
owner data, deployment, production checkpoint or Desktop consumption. Public
release precedes Desktop consumption. Mechanical qualification is not integrated
executor safety or semantic-quality certification.
